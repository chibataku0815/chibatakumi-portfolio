```ts

  font: opentype.Font | null;
```

## ⚠ NON-NEGOTIABLE constraints (read these before changing anything)

### 1. `THREE.DoubleSide` is mandatory on every mesh material

`wordmark-geometry.ts` line 64 calls `geom.scale(1, -1, 1)` to flip from SVG y-down to Three.js y-up. **This inverts triangle winding (CCW → CW)**. With the default `THREE.FrontSide`, every face becomes back-facing → fully culled → **canvas renders BLANK with no error or warning**.

Every `meshBasicMaterial` / `meshStandardMaterial` in any Scene that consumes these geometries MUST set `side={THREE.DoubleSide}`. The only material exempt is `lineBasicMaterial` (line segments have no winding).

The reference impl carries this exact comment — preserve it inline. Do not strip as "redundant."

### 2. `branding.wordmark` (Geist Medium) stays in production

`Nav.tsx` and `BrandWordmark.tsx` consume `portfolioData.branding.wordmark.{primaryPaths, secondaryPaths, viewBox}`. Removing it breaks the chrome. The hero divergence (Jost/Inter/Hanken/Bebas) is INTENTIONAL — hero ≠ chrome.

### 3. WOFF2 is not parseable

opentype.js 1.3.4 supports OTF / TTF / WOFF (v1). It does NOT support WOFF2. Any new font must come as one of those three formats. Don't link to Google Fonts CSS URLs (those return WOFF2 in modern browsers).

### 4. Font URL changes must work on cold cache

`useFont` caches Promises by URL. When toggling between candidates, the first time each font is fetched takes ~200-500ms (40-60KB file + parse). Playwright tests must wait ≥2500ms after `goto` for cold-cache loads. Hot cache is instant.

### 5. The `?font=` query param is the canonical addressing mechanism

Don't remove it. Playwright captures and direct linking depend on it. The lowercase label match against `CANDIDATES[].label` is case-insensitive but exact.

### 6. Dev server lock conflict

Running `bun run dev` twice fails with `Unable to acquire lock at .next/dev/lock`. The persistent server PID 9823 was running through this work. Use `lsof -nP -iTCP:3000` to verify before attempting to start a new one. If you need to restart, kill the existing PID first (but verify it's our process, not the user's).

### 7. Layout chrome bleeds through in headless Playwright

The experiment overlay uses `<div className="fixed inset-0 z-50 bg-[#0e0e0e]">` to cover layout chrome. But:
- Next.js DevTools "1 issue" badge (z-index unknown) appears top of overlay in dev mode
- WebGPU error overlay appears bottom in headless Chromium (motion-dot can't init under SwiftShader)

These are **not bugs in our code** — they're dev-environment artifacts. The Playwright spec filters "[motion-dot]" and "WebGPU" console errors as benign. In the user's normal Chrome (with WebGPU support), these don't appear.

### 8. React 19 lint rule: `react-hooks/set-state-in-effect`

Calling synchronous `setState` inside `useEffect` body triggers a lint error. The `use-font.ts` hook uses the React 19 "derive state from props during render" idiom to reset state on URL change. Don't add a synchronous `setState` to the effect body or it'll lint-fail.

Similarly: `react-hooks/immutability` flags direct mutations of objects returned from hooks. The reason `client.tsx` uses `<OrthographicCamera makeDefault zoom={...}>` from drei (declarative) instead of mutating `camera.zoom = ...` inside a `useEffect`.

#### Lever 5: Per-pair kerning overrides
For each font, manually examine the 11 pairs in `CHIBA TAKUMI` (CH HI IB BA A_ _T TA AK KU UM MI) and override pairs that look loose/tight relative to the rest:

