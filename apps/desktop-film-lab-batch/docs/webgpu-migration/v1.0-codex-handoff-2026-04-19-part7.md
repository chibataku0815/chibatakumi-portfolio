### 3.2 The orientation-contract fix (same commit)

During the session, a code-review flagged a **P1 bug** on the first
version of the above wiring: the temporal / central-bloom / shafts
passes were all originally bound to `offscreenFlagsBindGroup`. The
reviewer's analysis (confirmed correct on re-inspection) was:

- `offscreenFlagsBindGroup` (flipY=0) in the fullscreen vertex shader
  outputs `uv.y = uvRaw.y`, which at raster row 0 samples the source at
  `uv.y = 1` — i.e., it **flips Y**. This cancels the
  `copyExternalImageToTexture({flipY: true})` applied at media upload
  time, so `filmlab → rt.colorGraded` ends up upright.
- `crossFilterFlagsBindGroup` (flipY=1) outputs `uv.y = 1 - uvRaw.y`,
  which samples `uv.y = 0` at raster row 0 — i.e., **no flip**.
- After the cross-filter post-peak transition (`spacing-max-x`
  onwards), the chain lives on the no-flip contract, so
  `currentPeakTexture`, streak textures, and the blend output are all
  upright.
- Binding temporal / central-bloom / shafts to the offscreen contract
  added one extra Y flip in the middle of an otherwise-upright chain.
  The reviewer's high-confidence (0.93) diagnosis was that held peaks,
  the halo, and the shaft RT would all arrive mirrored relative to
  their scene input.

**Fix in the same commit**: all three rebound to
`crossFilterFlagsBindGroup`. Specifically:

- `crossfilter.temporal` pass → `crossFilterFlagsBindGroup`.
- `centralBloom.seed`, `centralBloom.downsample.*`,
  `centralBloom.upsample.*` → `crossFilterFlagsBindGroup`.
- `lightshafts.radial`, `lightshafts.blend` → `crossFilterFlagsBindGroup`.

Generic bloom/halation pyramids remain on `offscreenFlagsBindGroup`
because they feed `composite`, which runs under offscreen flags. The
rule carried forward: **any texture consumed inside `crossfilter.blend`
or `lightshafts.blend` must be produced under the cross-filter
(no-flip) contract.**

Headless gates were re-run after this fix and all stayed green.
