## 1. Final diagnosis — H1 confirmed

**The compare bar was never available on WebGPU on this branch.** It is
gated off by the backend capability surface, which is hard-coded on
WebGPU and frozen at GpuContext construction. Commit `8774de55`
(2026-04-19 — "feat(webgpu): Hard Mode parity + Light Shafts") did not
touch the capability surface, the Viewport publication path, the
`FilmLabCanvas` gate expression, or any path that would cause the
compare bar to disappear.

Root cause: **user expectation mismatch.** The user was comparing the
Desktop (WebGPU) build against a prior mental model sourced from the
web (WebGL) build — or from a pre-v1 WebGL-Desktop build. The compare
bar has been off on WebGPU for the entire life of
`feature/webgpu-migration-v1`.

## 2. Evidence

### 2.1 WebGPU compare flags were never `true` on this branch

- `packages/film-lab-renderer/src/webgpu/GpuContext.ts:67-78` freezes
  `supportsCompare: false`, `supportsBeforeAfter: false`,
  `supportsABCompare: false` at construction time. The object is
  `Object.freeze`-ed — not runtime-mutable.
- The first commit that introduced WebGPU capabilities on this branch
  was `3e205386` (2026-04-18 23:20:19 +0900). All three compare flags
  were `false` in that commit. No subsequent commit flipped them.
- `git log --all --oneline -- packages/film-lab-renderer/src/webgpu/GpuContext.ts`
  was audited — no flag flip found.

### 2.2 Desktop build always selects WebGPU; no `webgl` override exists

- `apps/desktop-film-lab-batch/vite.config.ts:126` hard-codes
  `"import.meta.env.FILMTONE_BACKEND": JSON.stringify("webgpu")`. The
  value is baked in at build time; there is no runtime way to switch
  the desktop bundle to WebGL.
- No `.env*` file in the repo (root, `apps/desktop-film-lab-batch/`,
  `apps/web/`) contains a `FILMTONE_BACKEND` entry. There is no stale
  `FILMTONE_BACKEND=webgl` override that could have been recently
  removed.
- The `FILMTONE_BACKEND` define was first introduced in commit
  `6e0b88e1` (2026-04-18 15:54:12 +0900) and has always been
  `"webgpu"` on this branch — never `"webgl"`.

### 2.3 The UI gate short-circuits before any driver is called

- `packages/film-lab-ui/src/FilmLabCanvas.tsx:1159-1161`:

  ```tsx
  const previewSupportsCompare =
    viewportCapabilities?.supportsBeforeAfter === true &&
    viewportCapabilities?.supportsABCompare === true;
  ```

- This expression is the single source of truth for:
  - cursor class (line 1554),
  - compare HUD render (line 1617),
  - pointer / drag handler attachment (line 1699).
- Under WebGPU, both flags are `false` → `previewSupportsCompare ===
  false` → none of the three compare surfaces ever renders.
- `packages/film-lab-renderer/src/Viewport.ts:330-336` defines the
  app-facing `setComparePair(...)` method as a delegate that uses
  `this.webglBackend?.setComparePair(...)`. On WebGPU `webglBackend`
  is null, so the call is a silent no-op. But because the UI gate
  above short-circuits earlier, `setComparePair` is not even reached
  from the UI on WebGPU.
- `WebGPUBackend.ts` has `frameState.splitPosition: -1` as a stored
  field only. There is no `setComparePair` method, no compare render
  path, no WGSL split shader. This matches part-6 §6.6 and part-7 §5.4.

### 2.4 `8774de55` is innocent of the capability surface

`git diff 8774de55~1..8774de55 --stat` for the compare-relevant files:

- `packages/film-lab-renderer/src/webgpu/GpuContext.ts` — **not
  touched**.
- `packages/film-lab-renderer/src/Viewport.ts` — **not touched**.
- `packages/film-lab-ui/src/FilmLabCanvas.tsx` — **not touched**.

Commit `8774de55` changed six files inside the WebGPU renderer
(Hard-mode cross-filter parity + Light Shafts + a new test file).
Nothing in those six files touches the capability surface.

### 2.5 H4 static-check: no validation-error smoking gun

Part-7 §4.6 H4 proposed that the new pipelines (`crossFilterTemporal`,
`lightshafts`, `lightshaftsBlend`) might validation-error at pipeline
creation, causing backend init to throw and `viewportCapabilities` to
stay `null` (which would also yield `previewSupportsCompare === false`).

Static evidence collected:

- `crossFilterTemporalGroupLayout` (WebGPUBackend.ts:561-569): **4
  entries** (uniform, texture, texture, sampler). Matches
  `cross-filter-temporal.frag.wgsl.ts` `@binding(0..3)`.
- `lightshaftsGroupLayout` (lines 572-579): **3 entries** (uniform,
  texture, sampler). Matches the radial shader's
  `@binding(0..2)`.
- `lightshaftsBlendGroupLayout` (lines 582-590): **4 entries**
  (uniform, uScene, uShafts, uSampler) at bindings 0, 1, 2, 3.
  Matches `lightshafts-blend.frag.wgsl.ts` `@binding(0..3)`. An
  intermediate investigation sub-agent reported this layout as
  declaring only 3 bindings; direct re-read confirmed **all 4 are
  present**. That report was a miscount.
- Uniform buffer sizes all 16-byte aligned and match the WGSL struct
  definitions (`uParams: vec4f` = 16 B, 2×`vec4f` = 32 B).
- Fragment target format (`rgba16float`) is consistent across all
  three new pipelines and matches the allocated render targets.
- Orientation contract: `crossfilter.temporal`, `centralBloom.*`,
  `lightshafts.radial`, `lightshafts.blend` all bind
  `crossFilterFlagsBindGroup` (no-flip), as §3.2 of part-7 requires.

Conclusion: **no static evidence of an init-time validation failure**.
If the user's preview is visibly rendering (i.e. they are not looking
at the `canvas.webgpuInitFailed` error UI), H4 is ruled out.

### 2.6 Post-commit uncommitted refactor is orthogonal to compare

Part-7 §1.2 documents a cohesive follow-up refactor on the
cross-filter temporal hold in the working tree (not yet committed):

- `crossFilterState.ts` adds `computeCrossFilterTemporalDecay(...)`
  + two new exported constants.

- `WebGPUBackend.ts` wires `lastCrossFilterHistoryTime` + per-frame

- `webgpu-cross-filter-state.test.ts` adds a 5-case describe block.

This refactor does not touch the capability surface, `FilmLabCanvas`,
`Viewport`, or `GpuContext`. It only affects Hard-mode temporal decay
correctness at varying frame cadences. **It is unrelated to the
compare-bar investigation.**
