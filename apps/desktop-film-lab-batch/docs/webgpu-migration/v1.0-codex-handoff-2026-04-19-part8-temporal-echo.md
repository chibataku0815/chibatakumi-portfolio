## 3. What `8774de55` had already introduced before this follow-up

`8774de55` was the large WebGPU migration-completion commit. The
cross-filter-related behavior relevant to this follow-up:

- WebGPU Hard Mode gained a temporal hold pass:
  - WGSL port of WebGL's temporal shader.
  - 2-slot half-resolution history ping-pong.
  - formula:
    - `prevMask = smoothstep(0.002, 0.03, luma709(prev))`
    - `held = prev * (0.82 * prevMask)`

- Hard-mode central bloom was rebuilt from the held peak mask.
- Diffusion was suppressed in Hard Mode.
- Light Shafts were inserted into the active WebGPU post tail.

  - `CrossFilter -> Shafts -> MotionBlur`

migration, with compare and dust still deferred.

## 4. Review findings that were raised after `8774de55`

The next chat should know the immediate post-commit review history,
because the current issue sits on top of those fixes.

Three P1 review findings were raised against the new WebGPU code in
`packages/film-lab-renderer/src/webgpu/WebGPUBackend.ts`:

1. Temporal hold used the wrong orientation contract.
   - It was bound to `offscreenFlagsBindGroup`.
   - The existing post-peak cross-filter chain expected
     `crossFilterFlagsBindGroup`.
   - Result: an extra Y flip would mirror the held peak mask relative to
     the source frame.

2. Central bloom mip chain was built under the wrong orientation
   contract.
   - Seed / downsample / upsample passes used the offscreen contract.
   - `crossfilter.blend` expected the cross-filter contract.
   - Result: halo contribution would be vertically misregistered.

3. Light shafts radial and blend passes used incompatible row orders.
   - Shaft texture and scene texture arrived at the blend pass with
     opposite row-order assumptions.
   - Result: shaft origin / decay would not align with the frame.

The user then reported that an orientation fix had been applied:

- temporal pass rebound to `crossFilterFlagsBindGroup`
- central bloom seed/downsample/upsample rebound to
  `crossFilterFlagsBindGroup`
- shafts radial + blend rebound to `crossFilterFlagsBindGroup`

Current source reflects that contract, and a follow-up review found no
remaining orientation findings in those areas.

Rule established from that review:

- Any texture consumed inside `crossfilter.blend` or
  `lightshafts.blend` must be produced under the cross-filter contract.
- Only the generic bloom / halation / diffusion pyramid that feeds the
  later composite path should live on the offscreen contract.

## 6. Root-cause analysis that was completed in this chat

The preview/export mismatch was traced to **temporal decay being applied
per render call instead of per elapsed time**.

### 6.1 Preview cadence

Preview pumps time from a RAF-driven clock:

- [FilmLabCanvas.tsx](/Volumes/SamsungPortableSSDX5001/documents/forestone/chibatakumi-portfolio/packages/film-lab-ui/src/FilmLabCanvas.tsx:1080)
- `viewport.setTime(clock.getElapsedTime())`
- [FilmLabCanvas.tsx](/Volumes/SamsungPortableSSDX5001/documents/forestone/chibatakumi-portfolio/packages/film-lab-ui/src/FilmLabCanvas.tsx:1092)

This usually runs around display refresh rate, often about 60 Hz.

### 6.2 Export cadence

Video export is fixed at 24 fps:

- [video-export-constants.ts](/Volumes/SamsungPortableSSDX5001/documents/forestone/chibatakumi-portfolio/apps/desktop-film-lab-batch/src/renderer/video-export-constants.ts:17)
- `VIDEO_EXPORT_FPS = 24`

Per export frame, the session time is set explicitly and then one render
is performed:

- [video-export-pipeline.ts](/Volumes/SamsungPortableSSDX5001/documents/forestone/chibatakumi-portfolio/apps/desktop-film-lab-batch/src/renderer/video-export-pipeline.ts:1138)
- [video-export-pipeline.ts](/Volumes/SamsungPortableSSDX5001/documents/forestone/chibatakumi-portfolio/apps/desktop-film-lab-batch/src/renderer/video-export-pipeline.ts:1142)
- [video-export-pipeline.ts](/Volumes/SamsungPortableSSDX5001/documents/forestone/chibatakumi-portfolio/apps/desktop-film-lab-batch/src/renderer/video-export-pipeline.ts:1264)

### 6.3 Why that caused the mismatch

The WebGL-authored temporal rule was "0.82 per frame." The original
WebGPU port used a fixed `0.82` every render. That means:

- preview at ~60 renders/sec decays more often per second
- export at 24 renders/sec decays less often per second

So export held highlights longer in real time, which looked like extra
afterimage even when preview and export were otherwise consistent.

This was a cadence bug, not a Y-orientation bug.

## 11. Likely implementation directions

These are not instructions to blindly follow. They are the most
plausible low-risk solution branches.

### Option A: Disable Hard-mode temporal hold entirely in WebGPU

Minimal behavior change:

- skip the temporal pass
- use `currentPeakTexture` directly as `heldPeakTexture`
- central bloom then seeds from current peaks instead of temporally held
  peaks

Tradeoff:

- simplest way to eliminate the trail
- strongest divergence from WebGL Hard-mode parity
- may make the effect harsher / thinner than the current migrated look

### Option B: Keep the temporal pass but reduce persistence sharply

Examples:

- lower the reference decay substantially below `0.82`
- clamp effective decay toward zero
- gate hold only above some brightness / mask threshold

Tradeoff:

- smaller product change than full removal
- still diverges from WebGL parity
- can leave a residual trail if tuned too conservatively

### Option C: Add a dedicated control or internal policy switch

Examples:

- expose a "temporal hold" amount
- make the current shipping preset use zero hold
- keep shader plumbing but default it off

Tradeoff:

- more flexible
- slightly larger scope because it touches UI / params / preset behavior

### Option D: Reset history more aggressively around seeks / source jumps

This is now less likely to be the main issue because preview and export
already match after the time-normalized fix, but it may still matter if
some trail appears on clip starts or discontinuities.

Tradeoff:

- useful only if the remaining complaint is about stale history across
  jumps rather than normal motion within a shot
- probably insufficient if the user simply dislikes the Hard-mode trail
  itself
