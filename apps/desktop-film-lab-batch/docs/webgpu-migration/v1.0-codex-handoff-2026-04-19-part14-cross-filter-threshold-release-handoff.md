Current key details:

- reducer normalization clamps `crossFilterMinSpacing` to `[1, 10]`

- both backends clamp to `[1, 10]`
- shader scan ceiling now covers the backend-authored public max radius
  for `10.00`
- both spacing-max shaders now use `MAX_RADIUS = 264`

Current spacing-radius mapping in both backends:

- baseline radius at `1.00` remains `48 px`
- each additional unit of spacing adds a smoothstepped `24 px` step of
  extra scan radius
- maximum authored radius at `10.00` therefore reaches `264 px`

This is why both `cross-filter-peak-spacing-max` shaders were updated to
`MAX_RADIUS = 264`.

### 5.3 Threshold semantics

The threshold control is now the recommended answer to the user's
"whether rays appear" request.

Important nuance:

- hard mode did not simply start using the raw stored threshold value
- doing that would have changed existing looks because presets and saved
  states commonly use `crossFilterThreshold = 0.92`

To preserve baseline appearance, both backends now use a compatibility
remap:

- control baseline:
  `CROSS_FILTER_THRESHOLD_CONTROL_BASELINE = 0.92`
- historical hard-mode baseline:
  `CROSS_FILTER_THRESHOLD_HARD_BASELINE = 0.70`
- hard-mode effective threshold:
  `threshold - (0.92 - 0.70)`, clamped into `[0, 1]`

Meaning:

- in hard mode, UI value `0.92` still reproduces the old effective
  onset threshold of about `0.70`
- lowering the slider below `0.92` makes rays appear more readily
- raising it above `0.92` makes rays harder to appear
- this gives the user direct control over "appearance vs suppression"
  without changing the accepted baseline by default

Relevant files:

- `packages/film-lab-renderer/src/webgl/WebGLBackend.ts`
- `packages/film-lab-renderer/src/webgpu/WebGPUBackend.ts`
- `packages/film-lab-ui/src/FilmLabControlPanelCore.tsx`
