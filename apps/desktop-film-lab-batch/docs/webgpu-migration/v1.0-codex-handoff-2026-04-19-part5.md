### 4.1 Base WebGPU cross-filter runtime integration

The session added the missing runtime wiring for the WebGPU
cross-filter path, including:

- cross-filter pipelines for:
  - `peak`
  - `peak-spacing-max`
  - `peak-spacing`
  - `streak`
  - `blend`
- supporting bind-group layouts for:
  - peak-spacing
  - blend
- cross-filter uniform buffers for:
  - threshold
  - peak
  - spacing-max x2
  - spacing
  - streak x4
  - blend
- pooled half-resolution working targets for:
  - threshold
  - peak
  - peak spacing work
  - peak spacing max
  - peak spaced
  - up to 4 streak outputs
- a black fallback texture for unused streak slots
- a focused `renderCrossFilter(...)` helper in WebGPUBackend
- post-chain insertion so the tail became:
  - `composite -> cross-filter -> blit`
  - or `composite -> cross-filter -> motion blur`

The WebGPU cross-filter helper reads the following params from
`frameState.params`:

- `crossFilterStrength`
- `crossFilterSpikes`
- `crossFilterAngle`
- `crossFilterLength`
- `crossFilterThreshold`
- `crossFilterChromatic`
- `crossFilterSizeLimit`
- `crossFilterRandomness`
- `crossFilterMinSpacing`
- `crossFilterHardMode`

It computes:

- `dirCount = floor(crossFilterSpikes / 2)` with clamping to available
  streak slots

It then runs:

- threshold extraction from the composited source
- peak detection
- optional spacing filtering
- directional streak generation
- final blend over the composited source

## 7. Current code state that likely explains the new glow regression

This is the most important section for the next chat.

The current code is in an inconsistent intermediate orientation state.

### 7.1 Generic pyramid code was accidentally contaminated with cross-filter flags

The generic `renderPyramidChain(...)` helper is used for bloom /
halation-style pyramids. It should almost certainly stay on the neutral
offscreen orientation contract.

However, it currently binds `crossFilterFlagsBindGroup` for the first
two stages:

- prefilter:
  - `packages/film-lab-renderer/src/webgpu/WebGPUBackend.ts:1377`
- progressive downsample:
  - `packages/film-lab-renderer/src/webgpu/WebGPUBackend.ts:1420`

But the same helper still uses `offscreenFlagsBindGroup` for upsample:

- upsample:
  - `packages/film-lab-renderer/src/webgpu/WebGPUBackend.ts:1464`

This mixed state inside the generic bloom / halation pyramid helper is
the strongest current root-cause candidate for:

- glow / light bleed rendering upside down while the cross-filter
  preview itself now looks correct

### 7.2 The cross-filter chain itself is also internally inconsistent

Within `renderCrossFilter(...)`, different subpasses currently use
different orientation flag groups.

Threshold and peak still use neutral offscreen flags:

- threshold pass:
  - `packages/film-lab-renderer/src/webgpu/WebGPUBackend.ts:1715`
- peak pass:
  - `packages/film-lab-renderer/src/webgpu/WebGPUBackend.ts:1754`

But later cross-filter subpasses use the dedicated cross-filter flags:

- spacing-max-x:
  - `packages/film-lab-renderer/src/webgpu/WebGPUBackend.ts:1808`
- spacing-max-y:
  - `packages/film-lab-renderer/src/webgpu/WebGPUBackend.ts:1852`
- spacing:
  - `packages/film-lab-renderer/src/webgpu/WebGPUBackend.ts:1892`
- streak:
  - `packages/film-lab-renderer/src/webgpu/WebGPUBackend.ts:1953`
- blend:
  - `packages/film-lab-renderer/src/webgpu/WebGPUBackend.ts:1998`

This means the current cross-filter chain is not yet orientation-clean
either. Some stages are neutral; later stages are flipped.

### 7.3 Display path split is still intentionally present

The final display / readback split is still in place and probably
should remain unless a later verification disproves it:

- `setFlipY(...)` writes only `displayFlagsBuffer` at:
  - `packages/film-lab-renderer/src/webgpu/WebGPUBackend.ts:1078`
- present / readback use `displayFlagsBindGroup`
- motion blur feedback remains on neutral offscreen flags

This split was a reasonable structural improvement and is not currently
the most suspicious part of the regression.
