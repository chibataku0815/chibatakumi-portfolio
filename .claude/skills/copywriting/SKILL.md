# copywriting

コピーライティング専門。ブランドメッセージング、価値の言語化、説得力のあるナラティブを設計する。

## Role Definition

- **責務**: タグライン開発、ヒーローコピー、About文、サービス説明、CTA設計
- **成果物**: コピー案（複数バリエーション）、トーン&マナーガイド、メッセージフレームワーク
- **境界**: 戦略的方向性は Brand Strategy から受領、実装は Frontend に委譲

## Philosophy: Words as Design

### Minimalist Copywriting

```
過剰なコピー（避ける）:
  「私たちは、お客様のニーズに寄り添い、
   最高品質のサービスを提供することで、
   皆様のビジネスの成功をサポートいたします」
  → 何も言っていない

ミニマルなコピー（推奨）:
  「一人で完結。意図を形に。」
  → 本質だけを残す
```

### The Power of Subtraction

```
編集プロセス:
  Draft 1: 思いつくままに書く
  Draft 2: 50%削る
  Draft 3: さらに50%削る
  Final:   削れないものだけが残る

「完璧とは、付け加えるものがなくなった時ではなく、
 取り去るものがなくなった時に達成される」
 — アントワーヌ・ド・サン＝テグジュペリ
```

## Tone & Voice Guidelines

### Voice Characteristics

| 特性 | 推奨 | 避ける |
|------|------|--------|
| **Confident** | 「〜します」 | 「〜できるかもしれません」 |
| **Concise** | 「一人で完結」 | 「一人ですべてを行うことが可能」 |
| **Direct** | 「翻訳ロスをなくす」 | 「コミュニケーションの齟齬を最小化」 |
| **Human** | 「あなたのビジョン」 | 「御社のご要望」 |
| **Specific** | 「10年来のクライアント」 | 「長年の実績」 |

### Tone Spectrum

```
このブランドのトーン:

Formal ←――――●―――→ Casual
         やや formal 寄り

Serious ←――●――――――→ Playful
         serious 寄り

Technical ←――●――――――→ Simple
            中間やや technical

Distant ←――――●―――→ Personal
          中間やや personal
```

### Language Rules

```
使う言葉:
✓ 一人で完結
✓ 統合
✓ 本質
✓ 視点
✓ 形にする
✓ 翻訳なしで

避ける言葉:
✗ ワンストップ（陳腐）
✗ トータルソリューション（空虚）
✗ お客様に寄り添う（曖昧）
✗ 最高品質（根拠なし）
✗ プロフェッショナル（自称）
✗ クリエイティブ（形容詞として単独使用）
```

## Copy Frameworks

### Hero Copy Structure

```markdown
## Hero コピー構造

### Primary Headline (最大インパクト)
[7語以内、本質を一撃で]

### Secondary Line (補足)
[Primary を補完、より具体的に]

### Tertiary (必要なら)
[行動を促す、または文脈を追加]
```

**Hero Copy Examples:**

```
Option A: 掛け算を可視化
  Primary:   Visual × Technology × Sound
  Secondary: 一人の視点で、すべてを形に。

Option B: 完結性を強調
  Primary:   One mind. Complete vision.
  Secondary: 写真、映像、Web、体験設計。
             翻訳なしで、あなたの意図を形に。

Option C: 本質主義
  Primary:   ノイズを削ぎ落とし、本質だけを残す。
  Secondary: フロントエンドエンジニア × デザイナー
             × フォトグラファー × ビデオグラファー

Option D: 対話的
  Primary:   あなたのビジョン、そのままに。
  Secondary: 複数のスキルが一人の中で統合される時、
             翻訳ロスは消え、意図だけが残る。
```

### About Section Framework

```markdown
## About 構造

### Hook (引き込み)
[最初の1文で興味を引く]

### Identity (何者か)
[スキルの統合を示す]

### Philosophy (なぜそうするか)
[価値観、美学]

### Value (クライアントへの価値)
[具体的なベネフィット]

### Call (次のステップへ)
[自然な流れで Contact へ]
```

**About Copy Example:**

```markdown
一人で、完結する。

写真家として光を捉え、
映像作家として時間を編み、
エンジニアとして体験を構築する。

これらは別々のスキルではない。
一つの視点が、異なる媒体で表現されるだけだ。

複数の専門家を介する度に、意図は薄まる。
翻訳が重なる度に、本質からは遠ざかる。

あなたのビジョンを、
そのまま形にできる人間がここにいる。
```

### Service Description Framework

```markdown
## サービス説明の構造

### What (何をするか)
[一言で明確に]

### Why It Matters (なぜ重要か)
[クライアント視点の価値]

### How It's Different (何が違うか)
[統合的アプローチの強み]

### Result (得られる結果)
[具体的なアウトカム]
```

**Service Copy Examples:**

```markdown
## Web Design & Development

デザインとコードを、同じ頭で考える。

デザイナーが描いた夢を、エンジニアが「技術的に無理」と
否定する場面を見たことがあるだろう。
ここでは、その断絶は存在しない。

美しいものを美しいままコードに落とす。
最新技術（Next.js, Tailwind）とAIネイティブな開発スタイルで、
スピードと品質を両立。

結果：あなたが思い描いたものが、そのまま画面に現れる。
```

```markdown
## Photography

撮る前に、使い方を知っている。

単なる写真撮影ではない。
Webのヒーロー画像として機能するか。
SNSでクロップした時にも成立するか。
印刷物で映えるか。

すべての出口を知っているから、
撮影現場での判断が変わる。

結果：後工程で「もう少しこうなら...」がなくなる。
```

### CTA Framework

```markdown
## CTA の構造

### Pre-CTA Context
[なぜ行動すべきかの文脈]

### CTA Copy
[行動を促す言葉]

### Post-CTA Assurance
[不安を取り除く補足]
```

**CTA Examples:**

```
避けるべき:
  「お問い合わせ」
  「今すぐ相談」
  「無料見積もり」
  → 汎用的すぎる、売り込み感

推奨:
  Pre:   「まずは、話しませんか。」
  CTA:   「30分の戦略セッションを予約」
  Post:  「売り込みはしません。
          あなたのビジョンを聞かせてください。」

  Pre:   「次のプロジェクトが見えてきた時に。」
  CTA:   「対話を始める」
  Post:  「返信は48時間以内に。」
```

## Technical Skill Translation

### Engineering → Business Value

| 技術表現 | クライアント向け表現 |
|---------|-------------------|
| Next.js, React | 「読み込み速度の速いサイト」→ 離脱率低下 |
| TypeScript | 「バグの少ない安定したシステム」→ 信頼性 |
| Tailwind CSS | 「保守しやすい設計」→ 長期的コスト削減 |
| Claude Code | 「AI活用の効率的な開発」→ スピードとコスト |
| パフォーマンス最適化 | 「Google検索で上位に」→ 集客力 |
| アクセシビリティ | 「誰もが使えるサイト」→ 社会的責任 + リーチ拡大 |

### Multi-Skill Integration → Client Value

```
技術的表現（内部）:
  「写真撮影 + 映像編集 + Webデザイン + フロントエンド開発
   をすべて一人で行う」

クライアント向け表現:
  「撮影現場で『これはWebのメインビジュアルに使える』と
   判断した瞬間、そのまま最終形まで持っていける。

   意図の伝言ゲームが発生しないから、
   あなたのビジョンがそのまま形になる。」
```

## AI-Native Development Messaging

### Positioning AI as Advantage

```
避けるべき:
  「AIを使って効率化しています」
  → 手抜き感、品質への不安

推奨:
  「反復作業はAIに任せ、
   創造的判断に集中する時間を最大化。
   人間の直感と、AIの実行速度。
   両方を活かす開発スタイル。」
```

### Specific Value Articulation

```markdown
## AIネイティブ開発の価値

従来の開発:
  創造的作業 30% + 反復作業 70%
  → 時間の大半が「手を動かす」ことに消費

AIネイティブ開発:
  創造的作業 70% + 反復作業 30%（AI支援）
  → 「考える」「判断する」に集中

結果:
  より良い判断 × より速い実行
  = 品質とスピードの両立
```

## Headline Writing Techniques

### The Power of Specificity

```
弱い:
  「豊富な経験」
  「高品質なサービス」
  「お客様満足度 No.1」

強い:
  「10年来のクライアントが、今も隣にいる」
  「撮影した日に、コードが書ける」
  「一人で完結するから、翻訳ロスがゼロになる」
```

### Contrast Creates Impact

```
対比を使う:
  「見た目の静けさ。触れた時の熱量。」
  「一人で完結する。でも、あなたのためだけに。」
  「派手さはない。でも、忘れられない。」
```

### Questions Engage

```
問いかけ:
  「あなたのビジョン、何人の手を経て形になっていますか？」
  「"技術的に無理" と言われたこと、ありませんか？」
  「本当に伝えたいこと、そのまま届いていますか？」
```

## Copy Variants & Testing

### A/B Testing Framework

```markdown
## コピーバリエーション

### Hero Headline
- A (Direct): 「一人で完結。意図を形に。」
- B (Question): 「あなたのビジョン、何人の翻訳を経ていますか？」
- C (Benefit): 「翻訳ロスゼロの、統合クリエイティブ。」

### CTA
- A (Action): 「対話を始める」
- B (Value): 「30分の戦略セッションを予約」
- C (Low-barrier): 「まずはメールで」

### 推奨
[コンテキストに応じた推奨とその理由]
```

## Anti-Patterns

- **空虚な形容詞**: 「最高の」「素晴らしい」「プロフェッショナルな」
- **陳腐なフレーズ**: 「お客様に寄り添う」「ワンストップ」「トータルソリューション」
- **過度な自己主張**: 自分がすごいではなく、クライアントに何が起きるか
- **曖昧な約束**: 「最高品質」より「翻訳ロスゼロ」という具体性
- **長文**: 読ませるのではなく、見せる。削れるものは削る
- **受動態**: 「〜されます」より「〜します」の能動態
- **業界用語**: クライアントが使わない言葉は使わない
